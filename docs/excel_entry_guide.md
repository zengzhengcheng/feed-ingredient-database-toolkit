# Excel 录入说明

本模板只收集两类公开数据：原料自身的成分，以及原料在特定试验动物上的营养价值。实验日粮组成不在本项目范围内。

Excel 是完整的数据贡献文件，论文元信息和数据都应写在文件中。PyQt6 不要求用户重新录入这些内容：选择文件后，软件会把元信息、原料、动物和数值全部显示在核对表中。用户只需处理错误或必要修正，确认前不会写入数据库。

**一份标准贡献工作簿只填写一篇论文。** `Studies`中只能有一条研究记录；需要贡献多篇论文时，请复制模板并拆成多个文件，再使用批量预检和批量导入。这样每篇论文都能独立核对、撤销和追溯。

## 最简单的判断方法

- 不需要知道动物也能解释的值，填入 `CompositionValues`。例如原料的粗蛋白、粗脂肪、水分、灰分和物理性质。
- 必须结合动物或试验才能解释的值，填入 `NutritionValues`。例如能量、AID、SID、ATTD、STTD。

## 可读编号

`study_key`、`trial_key`、`ingredient_key` 和 `animal_group_key` 只是同一工作簿内的连接编号。可以写成 `S001`、`T001`、`I001`、`A001`，不需要任何自动生成的编码。

## 推荐填写顺序

1. `Studies`：本工作簿只填写一篇论文，因此这里只能有一行。标题必填；DOI 可选，中文期刊没有 DOI 时留空。多篇论文必须拆分为多个工作簿，不要把 PDF 放进工作簿。
2. `Trials`：每个试验一行，用 `study_key` 指向论文。
3. `Ingredients`：每个原料样品一行，用 `study_key` 指向论文。
4. `AnimalGroups`：每个试验动物组一行，用 `trial_key` 指向试验。只有原料成分时可以不填。
5. `CompositionValues`：每行一个原料成分值。
6. `NutritionValues`：每行一个营养价值，同时连接 `ingredient_key` 和 `animal_group_key`。
7. `DictionaryCandidates`：遇到旧词典未收录的别名时，可提出统一名称建议。

`MetricCatalog` 是供查阅和筛选的常用指标目录，不是必须逐行填写的数据表。它把必需/非必需氨基酸、微量元素、维生素、抗营养因子和霉菌毒素等按组列出：`default_unit`是常用默认单位，`possible_units`列出该组分可能采用的单位。软件界面会把可能单位排在前面，同时保留完整单位列表。论文或原始表格明确报告的单位始终优先。

能量单位确实缺失时可以留空。软件先应用AME、DE、ME等指标专属规则；仍无专属规则时，再按数值量级建议单位：0.1–100为MJ/kg，500–<8000为kcal/kg，8000–100000为kJ/kg。落在其他区间时不猜测，要求人工核对。此过程只补单位标签，不换算或修改原始数值。原文明示单位仍优先，但若它和数值量级明显冲突，预检会提示用户回查原文。

## 干物质基础

- `dry matter`：数值已经换算到干物质基础。
- `as-fed`：数值按原样、风干样或饲喂状态报告。
- 原文没有说明时留空，不要猜测。

`Ingredients.reported_basis` 描述该原料列整体采用的基础；每个数值行的 `basis` 可覆盖它。`dry_matter_value` 保存原文报告的干物质含量，不在导入时自动换算其他数值。

## 原始名称与词典

`raw_name` 和 `raw_metric` 按论文或原 Excel 原样填写。软件会尝试用名称词典对应统一名称。没有匹配到时，数值仍会导入，名称状态记为 `candidate`，等待管理员确认。

## 录入前自查

- 每个 key 在本工作簿内唯一；
- 所有引用的 key 已在上游 sheet 中定义；
- 数值、单位和基础没有混在同一个单元格里；
- 能量和消化率没有误填到 `CompositionValues`；
- 没有实验日粮组成；
- 没有论文 PDF、截图或 OCR 文件。

## 在软件中核对并入库

1. 打开“导入与核对”；
2. 点击“选择 Excel / JSON”；
3. 核对文件识别出的论文元信息；
4. 分别查看原料与成分、动物信息、营养价值；
5. 点击“检查全部数据”；
6. 只有确认无阻断问题后，点击“确认写入工作数据库”。

未收录名称会作为 `candidate` 保存，稍后在“词典与指标”中统一处理，不需要在导入时逐项批准。同一文件名和论文标题已经成功写入后，再次保存会被阻止；修订文件应使用新的可读版本文件名。
